# 配置与数据

Ollupi 没有要手写的配置文件：模型、密钥、身份和每个身份的设置都在应用里改，保存后马上生效。这一页讲每样东西在哪改、数据存在哪、升级时旧文件怎么处理。这些在应用内部怎样存放和生效，见[配置的实现](/zh/desktop/config)。

## 数据在哪

后端的数据都在本机的 `~/.ollupi`，可以用环境变量 `OLLUPI_HOME` 换到别处：

| 位置 | 内容 |
|---|---|
| `~/.ollupi/data` | 数据库：模型服务和它们的 API 密钥，有哪些身份和它们的名字，以及每个身份的会话、记忆、待办、技能和设置 |
| `~/.ollupi/attachments` | 随消息发送的文件的副本 |
| `~/.ollupi/scratch` | 默认身份的第一个环境的文件夹：不属于工作区的会话在这里执行命令，MCP 服务器也在这里运行 |
| `~/.ollupi/super-agent` | 默认身份的 Super Agent 的文件夹 |
| `~/.ollupi/users/<身份>` | 别的身份的文件，和默认身份新建的其他环境的文件夹（`<环境>` 是环境的 ID）；只有一个身份、一个环境时没有这个文件夹 |
| `~/Library/Logs/Ollupi/backend.log` | 后端日志 |

**设置 → 通用** 里能直接打开 **应用日志**（就是上面的 `backend.log`）和 **数据文件夹**（`~/.ollupi`）。

后端起不来时，窗口会显示原因和后端日志，处理完点 **重启后端**，见[常见问题](/zh/app/troubleshooting)。

## 目录结构

```
~/.ollupi/
├── data/
│   └── store.sqlite     数据库，旁边有 -shm 和 -wal
├── attachments/         随消息发送的图片和文件的副本
├── scratch/             默认身份第一个环境的文件夹：不属于工作区的会话在这里执行命令
├── super-agent/         默认身份的 Super Agent 的文件夹
└── users/               有别的身份或别的环境时才有
    └── <身份>/
        ├── <环境>/       一个环境的文件夹
        └── super-agent/ 这个身份的 Super Agent 的文件夹（默认身份的在上面）
```

Super Agent 的文件夹以侧边栏 Super Agent 菜单里 **打开文件夹** 打开的为准。

agent 执行的命令读不到 `data/`，所以拿不到 API 密钥和数据库。删除一个环境时，它的文件夹留着，里面的文件不会丢。

::: info 演进
以前所有身份不属于工作区的会话都在同一个 `~/.ollupi/scratch` 里执行命令，MCP 服务器在 `~/.ollupi/users/<身份>` 里运行。现在每个环境有自己的文件夹：默认身份的第一个环境仍是 `scratch`，Super Agent 仍是 `super-agent`，别的身份和环境的在 `users/` 下。0.8.17-beta.13 一度让所有环境都用 `users/<身份>/<环境>`，下一版改回现在这样。
:::

应用自己的数据在 macOS 的标准位置，不在这个目录：

| 位置 | 内容 |
|---|---|
| `~/Library/Logs/Ollupi/backend.log` | 后端日志，超过 10 MB 时换新文件，上一份是 `backend.log.old` |
| `~/Library/Application Support/Ollupi/profile.json` | 这台 Mac 上的窗口用哪个身份 |
| `~/Library/Application Support/Ollupi/remote.json` | 连接另一台机器上的后端时的地址和密钥，加密保存 |
| `~/Library/Application Support/Ollupi/bookmarks.json` | 浏览器收藏 |
| `~/Library/Application Support/Ollupi/history.json` | 浏览器历史 |
| `~/Library/Application Support/Ollupi/browser-permissions.json` | 内置浏览器里各网站的权限 |
| `~/Library/Application Support/Ollupi/Partitions/browser` | 内置浏览器的 Cookie 和登录状态 |
| `~/Library/Application Support/Ollupi/update` | 下载的更新，启动时清空 |
| `<系统临时目录>/Ollupi/attachments` | 待发送的粘贴文件，启动时清空 |

配色、语言、通知开关和面板宽度存在应用界面自己的存储里，跟着这台 Mac，不跟着身份。

## 首次启动

全新安装第一次打开时，后端自己建好数据目录和第一个身份，但还没有模型。打开 **设置 → 模型** 添加一个模型服务，填上 API 密钥，就能开始会话，见[安装与上手](/zh/app/install)。

## 模型和 API 密钥 {#models}

模型服务（提供方）、它们的模型和 API 密钥都在 **设置 → 模型** 里添加和修改，存在后端的数据库里。所有身份共用这一份模型列表：

| 想做的事 | 怎么做 | 会发生什么 |
|---|---|---|
| 添加一个模型服务 | **添加提供方**，选 API 类型，填 Base URL 和密钥，从拉到的列表里选模型 | 保存后马上能用，不重启后端 |
| 改密钥、地址或模型的设置 | 编辑这个提供方或模型 | 新的一轮马上用上；正在调用模型的那一轮用原来的设置跑完 |
| 删除提供方或模型 | 卡片上的删除 | 选过它的身份要重新选。删不掉最后一个模型 |
| 选本身份新会话默认用哪个模型 | 点模型右边的星标 | 只影响这个身份。没选过的身份用第一个提供方的第一个模型 |

每个模型能设的几项：

| 项 | 不填时 | 含义 |
|---|---|---|
| 并发调用 | 4 | 同时最多向这个模型发几个请求，所有身份共用这个上限 |
| 思考 | Anthropic、Gemini 开启；OpenAI 兼容的不发送这一项，由服务自己决定 | 是否请求模型的思考 |
| 支持图片 | 关 | 关着时不给这个模型发图片 |
| Token 上限：上下文 | 必填 | 模型的上下文窗口 |
| Token 上限：输出 | 必填 | 一次回答最多多少 token |
| Token 上限：最大输入 | 窗口减去留给回答的部分（输出和窗口四分之一中较小的那个） | 模型的输入上限比这个小时填写 |

提供方的名字不能含 `/`，也不能和别的重名，因为模型按 `提供方/模型名` 区分，比如 `openai/gpt-5.2`。Gemini 必须填密钥。保存时后端会检查，不通过就提示原因，原来的设置不变。

### 连接另一台机器上的后端时

在 **设置 → 连接** 里连到另一台机器上的后端时，能不能改模型取决于填的 token：

- 填的是那台机器的运营者 token（`OLLUPI_OPERATOR_TOKEN` 加 `.<身份>`）：和本机一样能添加、修改模型。
- 填的是普通的网关 token（`OLLUPI_GATEWAY_TOKEN` 加 `.<身份>`）：**设置 → 模型** 显示「这个连接只能从已有的模型里选。添加和修改模型由后端的运营者来做。」，只能点星标选默认模型。

token 里的身份必须是那台后端上已有的身份，否则连接会被拒绝。连本机的后端时，应用自己就是运营者，不用填 token。

## 身份

身份在 **设置 → 身份** 里管理，身份和它们的名字存在后端的数据库里：

| 想做的事 | 怎么做 | 会发生什么 |
|---|---|---|
| 新建一个身份 | **新建身份**，起个名字 | 窗口马上换成新身份。它带着应用自带的技能，模型列表和其他身份共用 |
| 改名 | 编辑这个身份 | 马上生效，所有窗口一起更新 |
| 换这台 Mac 用的身份 | 身份右边的 **切换到它** | 记在这台 Mac 上，下次打开还是它 |
| 删除一个身份 | 身份右边的删除 | 它的会话、记忆和设置一起删掉。正在用的身份要先切走才能删；删不掉最后一个身份 |

全新的数据目录第一次启动时，后端自己建第一个身份，没有名字的身份显示成"我"。这台 Mac 记着的身份被删了，就退回第一个。

连另一台机器上的后端时，填运营者 token 才能新建、删除和切换身份；填普通 token 只看得到自己，可以给自己改名。

## 在应用里设置的

每个身份自己的选择也存在后端的数据库里，在应用里改，保存后马上生效，不重启后端：

| 设置 | 在哪改 |
|---|---|
| 新会话默认用哪个模型 | **设置 → 模型**，点模型右边的星标 |
| 学习记忆用哪个模型 | **记忆 → 全局**，见[定时任务与记忆](/zh/app/automation#设置) |
| 记忆开关、从会话中学习 | **记忆 → 全局** |
| 所有会话默认的审批策略和例外规则 | **设置 → 权限**，见[审批与权限](/zh/app/permissions#选一档审批策略) |
| MCP 服务器 | **能力 → MCP**，见[技能、MCP 与工具](/zh/app/capabilities#mcp) |
| 技能和给哪些 agent | **能力 → 技能**，见[技能、MCP 与工具](/zh/app/capabilities#技能) |

## 后端自己定好的 {#字段}

有几样东西不能改，所有身份都一样：

- agent 用 Ollupi 默认的系统提示词，所有工具都打开。
- 整个后端同时最多 32 个会话在运行，多出来的排队，等前面的空出位置。
- 命令和文件工具总是打开：命令只能写工作区（不在工作区时是所在环境的文件夹）、不能联网，默认 30 秒超时，单次最多 600 秒，见[沙箱](/zh/engine/sandbox)。

## 升级时自动处理的

从较早的版本升级时，`~/.ollupi` 里可能还留着 `config.yaml` 和 `profiles.json`。应用每次启动时，在启动后端之前先看一遍，把里面还有用的东西搬进数据库，再删掉这两个文件：

| 旧文件里有 | 启动时怎么处理 |
|---|---|
| 按身份写的模型 | 所有身份用过的模型合并进数据库里的模型列表；每个身份原来的默认模型和学习模型变成它自己的选择，名字也搬进去 |
| 模型服务列表 | 整个搬进数据库，换掉数据库里原有的模型列表。密钥从此只在数据库里 |
| `profiles.json`（旧版的身份列表） | 里面的身份和名字搬进数据库，颜色不要了，再删掉这个文件 |
| 技能文件夹 | 文件夹里的技能给每个已有身份，同名的合成一个、给原来有它的所有 agent（内容不同时以主 agent 那份为准）；文件夹原样留在磁盘上，可以自己删 |

这些都搬完后，`config.yaml` 被删掉，不留备份。文件里的其余内容不保留：自定义的名字、提示词、工具白名单和同时运行的会话数一律换成[后端自己定好的](#字段)那几样；更早版本留在文件里的权限、MCP 服务器和记忆开关也随文件删掉，要到应用里重新设置。

搬迁中途断了或没成功，后端照常启动，下次启动接着做完。这时 **设置 → 模型** 里可能暂时看不到原来的模型，退出 Ollupi 再打开一次即可。
