# 飞书机器人

在手机上通过飞书（或 Lark）的机器人操作 Ollupi 的会话：给它发消息开始会话，在它回复的话题里接着说，用它发来的卡片审批和回答。机器人用长连接主动连到飞书，这台 Mac 不需要公网地址，但要开着、不能睡眠。

## 在设置里接上

打开 **设置 → 飞书机器人**，填这几项：

| 项 | 填什么 |
|---|---|
| App ID | 飞书开放平台给的 `cli_` 开头的应用 ID |
| App Secret | 同一页的密钥，旁边的眼睛按钮可以显示或隐藏它 |
| 平台 | 飞书（open.feishu.cn）或 Lark（open.larksuite.com），要和应用所在的平台一致 |
| 为谁操作 | 每行一个 open_id。给机器人发条消息，它会回复你的 open_id；不在名单里的人发来的消息一律不处理。桌面端开始的会话会发到第一个人的单聊里 |
| 新会话所在的工作区 | 给机器人发消息时，在这个工作区里开始会话；也可以选「不属于任何工作区」。已归档的工作区不在列表里 |

填好 App ID 和 App Secret、并且确实改了内容之后，**保存并重启** 才可以点。保存后后端重启，机器人开始往外连接。

已经配置好时，这一页还有 **停用**：确认后它的设置被删掉，后端随即重启，机器人不再连接。

## 开放平台这边

1. 在[飞书开放平台](https://open.feishu.cn/app)（Lark 用 open.larksuite.com）创建**企业自建应用**，在「添加应用能力」里加上**机器人**。
2. 在「凭证与基础信息」复制 App ID 和 App Secret，填进 Ollupi。
3. 在「权限管理」开通两项权限：读取用户发给机器人的单聊消息，以应用的身份发消息。
4. 在「事件与回调」里：
   - 事件配置：订阅方式选**使用长连接接收事件**，添加事件「接收消息」（`im.message.receive_v1`）。
   - 回调配置：订阅方式选**使用长连接接收回调**，添加回调「卡片回传交互」（`card.action.trigger`）。
5. 在「版本管理与发布」创建版本并发布，可用范围只选你自己就够。
6. 在飞书里搜到这个机器人，给它发一条消息。它会回复你的 open_id，把这行填进 **为谁操作**，再保存一次。

机器人靠长连接收消息，所以这台 Mac 要开着、不能睡眠；关掉应用时它收不到消息。

## 在飞书里怎么用

- **开始会话**：在和机器人的单聊里直接发一条消息。机器人在这条消息下开一个话题，会话就在这个话题里；设了工作区就在那个工作区开始，没设就不属于任何工作区。
- **接着说**：在话题里回复。上一轮还没跑完时，消息会排队，机器人回一句「已排队，前面的消息处理完后回复。」
- **停止**：点这一轮卡片上的 **停止**，或在话题里发 `/stop`。
- **进度**：每一轮一张卡片（子 agent 的轮次不出卡片），agent 的回复和它调用的工具会陆续追加上去。在桌面端或由定时任务发起的轮次会注明来源。
- **审批和回答**：会单独发一张卡片，点按钮审批，或者填好答案后提交。「总是允许」要写规则，只能在桌面端操作。
- **两边的结果互通**：在飞书或桌面任意一端处理，卡片会更新成处理结果。
- **桌面端的会话**：在桌面端或由定时任务开始的会话，第一次开始一轮、或有审批和提问时，机器人发一条写着「工作区 · 标题」的消息，会话就在这条消息下的话题里，之后和从飞书开始的会话一样。名单里有好几个人时发给第一个人；子 agent 的会话不单独开话题，它的审批发到所属会话的话题里。

只处理单聊和名单里的人，只处理文字消息（包括富文本消息里的文字），图片和文件不处理。代码和对话内容会经过飞书的服务器。

卡片、排队和话题这些机制，以及和桌面端同时使用时的细节，见[飞书机器人的实现](/zh/desktop/feishu-bot)。
