# 技能、MCP 与工具

agent 能做什么，取决于它手上有哪些工具和技能。侧边栏的 **能力** 把这些集中在一处：左边一列切换 **技能**、**MCP**、**内置工具**。这一页讲怎样加技能、接 MCP 服务器，以及内置工具列表上的标记是什么意思。它们在引擎里怎样加载、怎样进上下文，见[技能与 MCP 的机制](/zh/engine/skills-mcp)。

技能和 MCP 服务器都是后端启动时加载的，所以在能力页里保存任何改动，都会先检查，再重启后端。重启时正在运行的一轮会被打断，后端起来后它从停下的地方接着跑；执行到一半的命令不会自动重跑，agent 会被告知去确认它有没有生效。

## 技能

技能是一个文件夹，里面有一份 `SKILL.md`：名称、一段"什么时候用"的描述，以及启用后 agent 要遵循的指令。agent 平时只看得到每个技能的描述，判断用得上时才读其余内容，所以技能多了也不会占满上下文。

### 开启和关闭

新安装的应用默认开启技能，技能放在 `~/.ollupi/skills`，里面有一个自带的版画风格配图技能。这之后这个文件夹归你管理，升级应用不会覆盖它。

| 想做的事 | 怎么做 | 会发生什么 |
|---|---|---|
| 开启技能 | 技能未开启时点 **开启** | 在数据文件夹里建一个技能文件夹并开始使用 |
| 换一个文件夹 | 点 **更换…**，选一个文件夹 | agent 改用那个文件夹里的技能 |
| 关闭技能 | 点 **关闭** | agent 不再使用技能，文件夹原样保留 |

文件夹路径旁边的图标可以在访达里打开它。

### 新建

点 **新建技能**，填三项：

| 项 | 写什么 |
|---|---|
| 名称 | 1 到 64 个小写字母、数字或单个连字符，不能以连字符开头或结尾，比如 `release-notes`。它同时是文件夹名 |
| 描述 | 它做什么、什么时候该用。agent 只凭这段话决定要不要启用这个技能，所以要写清触发的场景 |
| 指令 | 启用后 agent 遵循的 Markdown。不要超过 500 行，细节放到同一个文件夹里的其他文件 |

点 **保存并重启**。技能先按后端的规则检查，不通过时对话框里显示原因，什么都不写入；通过后才放进文件夹，后端重启加载它。

### 导入、编辑、删除

- **导入文件夹…**：选一个包含 `SKILL.md` 的文件夹，以原文件夹名复制进来。文件夹名必须和技能名称一致；技能文件夹里已有同名文件夹时拒绝导入。
- **编辑**：鼠标移到技能上，点铅笔图标，直接改 `SKILL.md`。frontmatter 里的名称必须和文件夹名一致。技能的其他文件不在这里改，点文件夹图标在访达里打开后再改。
- **删除**：点垃圾桶图标，确认后技能文件夹移到废纸篓，后端重启。

每个技能下面列出它的描述、版本（如果写了）和附带的文件。

agent 运行的命令只能读技能文件夹，不能改，见[配置与数据](/zh/app/config)。

### 直接在文件夹里改

你也可以不经过能力页，直接在访达或编辑器里改技能文件夹。这时后端还是用启动时加载的那一份，能力页会提示"文件夹中的技能与后端启动时加载的不一致"，点 **重启后端** 让改动生效。

直接改的技能没有经过检查。如果某个技能写坏了，能力页会显示"在修复以下问题之前，后端无法用这个文件夹启动"和具体原因，改好之前后端起不来，见[常见问题](/zh/app/troubleshooting)。

## MCP

MCP 服务器给 agent 提供额外的工具，比如读写 GitHub issue、查数据库。接上之后，服务器的工具以 `<服务器名>__<工具名>` 的名字出现，例如服务器叫 `github`，它的 `create_issue` 工具就是 `github__create_issue`。

### 添加服务器

点 **添加服务器**，先填名称，再选传输方式：

| 传输方式 | 填什么 |
|---|---|
| 命令（stdio） | **命令**，在登录 shell 的 PATH 里查找，比如 `npx`；**参数**，每行一个；**环境变量**，每行一个 `KEY=value` |
| URL（Streamable HTTP） | **URL**，比如 `https://example.com/mcp`；**Headers**，每行一个 `Name: value`，随每个请求发送 |

名称是 1 到 32 个字母、数字、`-` 或 `_`，以字母或数字开头，不能包含 `__`，也不能叫 `browser`，这个名字归内置浏览器。

点 **保存并重启**。配置先交给后端检查，不通过时提示"config.yaml 未修改"和原因，文件不变；通过后才写入，后端重启并连接服务器。

### 密钥不写进文件

环境变量和 Headers 的值里可以写 `${NAME}`，引用你在 `~/.zshrc` 里 `export` 的变量：

```text
Authorization: Bearer ${GITHUB_TOKEN}
```

这样密钥留在你的 shell 配置里，`config.yaml` 里只有变量名。保存时后端会检查变量是否已设置；引用的变量没设置，配置会被拒绝，因为服务器拿不到密钥就跑不起来。

编辑已有服务器时，写死在文件里的值显示为"（写在 config.yaml 中）"。不动这一行就保留原值，改掉就替换。

### 连接状态

每个服务器一张卡片，标出传输方式和状态：

| 状态 | 意思 | 怎么办 |
|---|---|---|
| 已连接 · N 个工具 | 后端连上了，提供 N 个工具，工具名列在卡片底部 | 无 |
| 未连接 | 后端启动时没连上，卡片里显示原因 | 按原因修好命令、地址或密钥，保存或重启后端 |
| 未启动 | 后端启动时还没有这个服务器，比如你刚手改了 `config.yaml` | 点 **重启后端** |

连不上的服务器只是被跳过，不影响后端启动和其他服务器。卡片上还可能列出"未提供"的工具：这些工具加上服务器名前缀后，名字不被模型 API 接受，所以没有交给 agent。

点 **刷新状态** 重新读一次。手改 `config.yaml` 后，能力页会提示"config.yaml 中的 MCP 服务器与后端启动时的不同"，点 **重启后端** 生效。

### 改名和删除

- 改名会改变这个服务器所有工具的名字，写着旧工具名的例外规则要跟着改。
- 删除服务器时它的工具一并移除。

### 服务器在哪里运行

MCP 服务器不在 agent 命令的沙箱里。它在 `~/.ollupi` 下以你的身份运行，能访问你的账号能访问的文件和网络，继承你登录 shell 的环境变量。所以只添加你信任的服务器。

## 内置工具

**内置工具** 列出 agent 自带的工具，来自引擎和这个应用的内置浏览器，按来源分组。MCP 服务器的工具不在这里，列在 MCP 下各自的服务器卡片里。

每个工具旁边可能有三种标记：

| 标记 | 意思 |
|---|---|
| 只读 | 不改任何东西 |
| 破坏性 | 可能删除或覆盖东西 |
| 外部 | 会接触这台电脑以外的东西，比如网络。工具没有声明自己不接触外部时，都标这一项 |

这里的名字就是例外规则里写的工具名，比如 `run_command`、`web_fetch`。

## MCP 工具和审批

MCP 工具和内置工具一样经过审批策略，判断依据是服务器自己声明的"只读""外部"标记：

| MCP 工具 | 严格 | 适中 | 宽松 |
|---|---|---|---|
| 声明只读，且声明不接触外部 | 直接做 | 直接做 | 直接做 |
| 声明只读，没声明不接触外部 | 先问你 | 直接做 | 直接做 |
| 没声明只读 | 先问你 | 先问你 | 直接做 |

标记是服务器自报的，应用无法验证。对不熟悉的服务器，可以用例外规则让它的工具总是先问你。

例外规则对 MCP 工具只能写到工具名，比如 `github__create_issue`，不能像 `run_command(git:*)` 那样在括号里限定范围。审批策略和例外规则怎么设，见[审批与权限](/zh/app/permissions)。

字段的完整含义见[配置与数据](/zh/app/config#mcp)。
