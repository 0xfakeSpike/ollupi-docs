# 技能、MCP 与工具

agent 能做什么，取决于它手上有哪些工具和技能。侧边栏的 **能力** 把这些集中在一处：**技能**、**MCP**、**内置工具** 三个分区，窗口窄时它们变成顶部一排可以横向滑动的标签。这一页讲怎样加技能、接 MCP 服务器、看懂内置工具列表上的标记，以及能让哪几种帮手去做事。它们在引擎里怎样加载、怎样进上下文，见[技能与 MCP 的机制](/zh/engine/skills-mcp)。

## 技能

技能是写给 agent 的一份做事方法：名称、一段「什么时候用」的描述、启用后 agent 要遵循的指令，有时还带几个脚本或参考文件。agent 平时只看得到每个技能的描述，判断用得上时才读其余内容，所以技能多了也不会占满上下文。

技能是每个身份自己的，存在后端里，不在哪个文件夹里。新身份第一次打开时，主 agent 已经有一个自带的配图技能；之后它归你管理，删掉就不会再回来。

### 给哪些 agent

一个技能可以给一个或几个 agent：主 agent、Super Agent，或八种子 agent 里的任意几种。每个 agent 只看得到给了它的技能，比如只给写作子 agent 的技能，主 agent 自己用不上。给主 agent 的技能用大模型和小模型时都在，会话换模型不会丢。

技能页把技能摆成卡片网格。卡片上写着技能名称、描述（太长时只显示前几行）和给了哪些 agent；技能自己写了版本时，名称右边有一个版本号。点开卡片就是编辑；鼠标停在卡片上，版本号的位置换成 ⋯ 菜单，里面是 **删除…**，确认后所有 agent 都不再有这个技能。

### 新建和编辑

点 **新建技能**，填这几项：

| 项 | 写什么 |
|---|---|
| 名称 | 技能的名字，agent 凭它启用技能。保存后不能再改 |
| 描述 | 它做什么、什么时候该用。agent 只凭这段话决定要不要用这个技能，所以要写清触发的场景 |
| 指令 | 启用后 agent 遵循的内容。不要超过 500 行，细节放到它带的文件里 |
| 给哪些 agent | 勾选要用它的 agent，至少一个，默认是主 agent |

点 **保存**。保存时先按后端的规则检查：通过就生效，agent 下一步就会用上，不用重启；不通过时对话框里显示原因，什么都不改。编辑同一个对话框，可以改描述、指令和给哪些 agent。技能带的文件在 **N 个文件** 里展开能看到路径，保存时原样保留，不在应用里改；agent 启用技能时，这些文件会放进它的沙箱。

### 导入文件夹

别人给你的技能通常是一个文件夹，里面有一份 `SKILL.md` 和旁边的脚本、说明。点 **导入文件夹…** 选中它，应用读出名称、描述、指令和文件，填进同一个对话框，你勾好给哪些 agent 再保存。文件夹名必须和技能名称一致。图片这类不是文本的文件不会带上，对话框里会列出来；已经有同名技能时，名称一栏会提示换一个。

## MCP

MCP 服务器给 agent 提供额外的工具，比如读写 GitHub issue、查数据库。接上之后，服务器的工具以「服务器名加两个下划线加工具名」的形式出现，例如服务器叫 `github`，它的 `create_issue` 工具就是 `github__create_issue`。

### 添加服务器

点 **添加服务器**，先填名称，再选传输方式：

| 传输方式 | 填什么 |
|---|---|
| 命令（stdio） | **命令**，在登录 shell 的 PATH 里查找，比如 `npx`；**参数**，每行一个；**环境变量**，每行一个 `KEY=value` |
| URL（Streamable HTTP） | **URL**，比如 `https://example.com/mcp`；**Headers**，每行一个 `Name: value`，随每个请求发送 |

名称只能用字母、数字、`-` 和 `_`，以字母或数字开头，不能包含两个连续的下划线，也不能叫 `browser`——这个名字归内置浏览器。

点 **保存**，马上生效，不用重启后端。

### 密钥

环境变量和 Headers 的值按你写的原样保存，密钥也一样，原样发给服务器。

命令（stdio）服务器还继承后端的环境变量，包括你在 `~/.zshrc` 里 `export` 的。如果服务器自己从环境变量读密钥，比如读 `GITHUB_TOKEN`，可以只在 `~/.zshrc` 里 `export` 它，这里不写。

### 连接状态

每个服务器一张卡片，标出传输方式和状态：

| 状态 | 意思 | 怎么办 |
|---|---|---|
| 已连接 · N 个工具 | 后端连上了，提供 N 个工具，工具名列在卡片底部 | 无 |
| 未连接 | 后端没连上它，卡片里显示原因 | 按原因修好命令、地址或密钥，再保存 |
| 用到时启动 | 还没用到过这个服务器，agent 要用它的工具时才启动 | 无 |

连不上的服务器只是被跳过，不影响其他服务器和其他功能。卡片上还可能列出「未提供」的工具：这些工具加上服务器名前缀后，名字不被模型 API 接受，所以没有交给 agent。

点 **刷新状态** 重新读一次。

### 改名和删除

- 改名会改变这个服务器所有工具的名字，写着旧工具名的例外规则要跟着改。
- 删除服务器时它的工具一并移除。

### 服务器在哪里运行

MCP 服务器不在 agent 命令的沙箱里。它以完全访问在你自己的账号下运行，工作目录是你第一个环境的文件夹，能访问你的账号能访问的文件和网络，继承你登录 shell 的环境变量（应用自己的密钥除外）。所以只添加你信任的服务器。

## 内置工具

**内置工具** 列出 agent 自带的工具，来自引擎和这个应用的内置浏览器，按用途分组：文件和命令、网页、浏览器、计划、问你、帮手、Super Agent、记忆、技能、定时任务、长输出、找工具。每组写着这类工具是什么，展开是具体的工具清单。MCP 服务器的工具不在这里，列在 MCP 下各自的服务器卡片里。

每个工具旁边可能有三种标记：

| 标记 | 意思 |
|---|---|
| 只看不改 | 不改任何东西 |
| 会改动东西 | 可能删除或覆盖东西 |
| 会接触外部 | 会接触这台电脑以外的东西，比如网络。工具没有声明自己不接触外部时，都标这一项 |

列表上的工具名就是写例外规则时用的名字。

## MCP 工具和审批

MCP 工具和内置工具一样经过审批策略。服务器可以给自己的工具标上「只看不改」「不接触外部」，但这些标记是服务器自报的，应用无法验证，所以审批时不采信，每个 MCP 工具都按「会改动东西」对待：

| MCP 工具 | 严格 | 适中 | 宽松 |
|---|---|---|---|
| 任何工具 | 先问你 | 先问你 | 直接做 |

经常用、又确定无害的工具，可以写一条例外规则让它直接做；不想让它做的，写一条规则禁止。

例外规则对 MCP 工具只能写到工具名，比如 `github__create_issue`，不能像命令那样在括号里限定范围；写规则时这个服务器要连着，否则规则被拒绝。审批策略和例外规则怎么设，见[审批与权限](/zh/app/permissions)。

## 可以让哪几种帮手去做事

主 agent 忙不过来、或者这件事更适合别的专长时，会把一部分工作派给帮手。这些帮手也各有自己的技能，就是技能页里每一节对应的那些：

| 帮手 | 适合交给它 |
|---|---|
| 通用子 agent | 一部分普通工作 |
| 浏览器子 agent | 在内置浏览器里办一件事 |
| 设计子 agent | 画一张图，把可修改的源文件留在结果旁边，并照着渲染出来的样子修 |
| 代码库子 agent | 读通整个项目并讲清楚它，不改动任何东西 |
| 前端子 agent | 做或改项目的界面——页面、组件、样式、布局——并在浏览器里确认渲染结果 |
| 后端子 agent | 改服务端、服务和命令行工具：接口处理、数据模型与迁移、并发 |
| 写作子 agent | 为一个明确的读者和场景写或改写一段文字，用这个人或项目的口吻 |
| 研究子 agent | 从公开网页、文档或项目文件里找信息，每个结论都给出出处 |

派给谁、什么时候派由它自己决定，你不用指定；结果会回到对话里。技能页里另外两节是主 agent 和 Super Agent：Super Agent 跨项目统筹，把每件事交给对应项目的会话，见[中枢](/zh/engine/hub)。
