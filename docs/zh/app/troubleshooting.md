# 常见问题

这一页按你看到的现象排列：看到什么、为什么、怎么办。每一节最后链接到讲透这件事的页面。

## 窗口里只有"后端无法启动"

Ollupi 由界面和一个在后台运行的后端组成，会话、模型调用、命令都在后端里。后端起不来时，整个窗口换成一页"后端无法启动"，上面有：

- 一行红色的原因；
- 配置文件的位置（原因跟配置有关时）；
- **重启后端** 和 **打开配置** 两个按钮；
- 可以展开的 **后端日志**，是这次启动最后的 200 行输出。

后端崩溃后不会自己重启，要你点 **重启后端**。原因有四种写法：

| 原因 | 意思 | 怎么办 |
|---|---|---|
| 后端在 30 秒内没有报告就绪 | 后端启动了，但 30 秒内没准备好，应用把它停掉了 | 展开后端日志看它卡在哪一步，再点 **重启后端** |
| 无法启动 …：… | 后端程序本身没能运行，后面是程序路径和系统给的错误 | 应用不会给出建议。程序本身起不来，多半是安装不完整，可以重新安装再试 |
| 后端意外退出（…） | 后端运行中退出了，括号里是退出码或信号 | 展开后端日志看退出前的最后几行 |
| 其他文字 | 后端自己说明了为什么不能启动，原样显示 | 大多是配置问题，见下一节 |

后端用的是你登录 shell 的环境变量（PATH、`~/.zshrc` 里 `export` 的变量）。shell 配置本身出错或很慢时，后端可能拿不到它们。

见[配置与数据](/zh/app/config)。

## 配置有错，后端拒绝启动

后端启动时检查 `config.yaml`，不合法就不启动，原因显示在"后端无法启动"页上，写明哪个文件、哪一项。例如：

```text
~/.ollupi/config.yaml still lists providers; ollupid --import-config moves them into the store, where the models are set in the app
```

```text
json: unknown field "permissions"
```

常见的几类：

| 原因里提到 | 通常是 | 怎么办 |
|---|---|---|
| 某个拼错或不认识的字段 | 手改时键名写错。未知字段会报错，不会被悄悄忽略 | 对照[字段表](/zh/app/config#字段)改正 |
| 不认识 `permissions`、`mcp`、`use` 或 `generate` | 跳过 0.7.53 直接升级，文件里还留着这几项。它们现在在应用里设置 | 删掉这几项，重启后端后到应用里重新设置，见[在应用里设置的](/zh/app/config#在应用里设置的) |
| `name is required`、`slots must not be negative` | `name` 空着，或 `slots` 写了负数 | 补上名字，或删掉 `slots` 用默认值 |
| `--import-config` | 文件里还有旧版本的写法，比如 `providers`、按身份写的模型、`skills_dir` 或 `workspace` | 退出 Ollupi 再打开：应用启动时会把它们改成现在的写法，模型搬进数据库，见[升级时自动处理的](/zh/app/config#升级时自动处理的) |

点 **打开配置** 改好文件，保存后点 **重启后端**。

应用本身不改这个文件，所以只有手改才会走到这一步。模型不在这个文件里：在 **设置 → 模型** 里保存时，不合规则的改动（比如提供方重名、名字带 `/`、Gemini 没填密钥）会被后端退回，提示「无法保存模型：」和原因，原来的模型不变。

## 改了配置或技能，没有生效

后端只在启动时读 `config.yaml`。手改了这个文件之后，界面不会提示，到 **设置 → 通用** 点 **重启后端** 才生效。

模型和密钥、默认模型、学习记忆的模型、技能、权限、MCP 服务器和记忆、学习两个开关都不在 `config.yaml` 里，在应用里保存就生效，不用重启后端：新的一轮马上用上新的模型设置，agent 每一步开始时都重新读技能。

在 **设置 → 模型** 里看到「这个连接只能从已有的模型里选。」，说明你连的是另一台机器上的后端，用的是普通 token，只能选默认模型，不能添加和修改。要改模型，到 **设置 → 连接** 换成那台机器的运营者 token，见[连接另一台机器上的后端时](/zh/app/config#连接另一台机器上的后端时)。

## 模型调用出错

### 一轮停在"这一轮失败了"

模型调用失败时，这一轮结束，对话里显示失败原因。原因是模型服务商返回的原文，按内容判断：

| 原因里提到 | 通常是 | 怎么办 |
|---|---|---|
| 401、unauthorized、invalid API key | API 密钥错了或没填 | 在 **设置 → 模型** 里编辑这个提供方，填对密钥 |
| 404、model not found | Base URL 或模型名称不对 | OpenAI 兼容的地址要带版本，比如 `.../v1`；模型名称要和服务商的一致 |
| 上下文过长、超出窗口 | 模型的 Token 上限填得比实际大 | 按模型的实际窗口填上下文和最大输入 |
| 带图片的消息被拒 | 这个模型没开"支持图片" | 模型支持图片就打开这一项，否则换一个模型 |

改好后重新发送消息。

### 429、服务器错误、连接断开

遇到限流（429）、服务商的 5xx 错误或连接断开，应用会自动重试，最多重试 8 次，前后约 40 秒。这期间这一轮只是变慢，你不需要做什么。

重试完还不行，这一轮才失败。如果经常遇到限流，在 **设置 → 模型** 里调低这个模型的 **并发调用**，让同时发出的请求少一些。

回答已经开始输出之后连接才断开，不会重试，这一轮失败，已经显示的内容保留。

见[模型接入](/zh/engine/models#重试)。

### 拉不到模型列表

添加提供方时提示"无法获取模型列表"，后面是原因。通常是 Base URL 或 API 密钥不对，改好后会重新拉取。

## 命令被沙箱拦下

命令的输出下方出现黄色的"沙箱：…"，说明这条命令有一步被沙箱挡住了，后面写着被挡的操作和路径或地址，比如写某个文件、连某个网站。只有命令失败时才显示。

这是沙箱在正常工作：命令只能改工作区和临时目录里的文件，读不到凭据类文件。agent 看得到这些原因，需要时它会申请完全访问，在严格和适中两档下会先问你，你在审批卡片上决定。

沙箱里的命令永远读不到 `~/.ollupi` 里的 `config.yaml` 和数据文件夹，这样它们拿不到你的 API 密钥和会话数据库。批准完全访问的命令不受这条限制，所以审批这类命令时要多看一眼。

见[审批与权限](/zh/app/permissions#沙箱是什么)。

## MCP 服务器"未连接"

能力页里 MCP 服务器的卡片显示"未连接"时，卡片下方有原因。连不上的服务器只是被跳过，不影响其他功能。按原因修好命令、URL 或密钥，点 **保存**，马上生效，不用重启后端。

卡片显示"用到时启动"不是故障：这个服务器还没用到过，agent 要用它的工具时才启动。见[技能、MCP 与工具](/zh/app/capabilities#连接状态)。

## 侧边栏显示"正在重新连接…"

界面和后端之间的连接断了，应用会自己不断重连，下方显示上一次失败的原因。后端还在运行时，通常几秒内就能连上。

## 日志在哪

后端日志在 `~/Library/Logs/Ollupi/backend.log`。**设置 → 通用** 的 **应用日志** 一行显示这个路径，旁边的按钮可以直接打开它。

文件超过 10 MB 时，下一次启动会把它改名为 `backend.log.old`，覆盖上一份旧日志，再写新文件。

"后端无法启动"页上展开的后端日志只是这次启动的最后 200 行；更早的内容在这个文件里。

## 从头开始

想让配置回到新安装的样子：

1. 退出 Ollupi。
2. 把 `~/.ollupi/config.yaml` 改名，比如改成 `config.yaml.bak`。
3. 重新打开 Ollupi。

找不到配置文件时，后端会写入一份新的模板。模型和密钥、技能、会话和记忆都在 `~/.ollupi/data` 的数据库里，不受这一步影响。

要连它们一起清掉，在退出后把 `data` 文件夹也改名移走；移走后所有模型、会话、记忆和定时任务都看不到了，要重新添加模型提供方，见[安装与上手](/zh/app/install#添加模型提供方)。各个文件夹放的是什么，见[配置与数据](/zh/app/config#数据在哪)。
