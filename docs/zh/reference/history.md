## 一、开端：一个 Go 库（10-17 – 10-23）

**4 个提交**：10-17 一个，10-18 一个，10-23 两个。

`acfb8e4` 是全部提交的起点，而且不是骨架：一次带上 ReAct 循环、线程与调度、工具注册表、权限与审批、Seatbelt 沙箱、模型边界脱敏、生成式记忆、对齐 Codex app-server 的 JSON-RPC 网关、cron 和 SQLite。README 的定位是「Go 写的 agent 运行时库……任何人都可以 import 它」，参考应用是 shenshiagent。顶层是扁平的一组包：`agent`、`thread`、`storage`、`memory`、`sandbox`、`gateway`、`cron`、`llm` 等。

次日只有一次改动（`ea46fff`），之后 10-19 到 10-22 没有提交。10-23 收结构：`bd1f4d1` 把包收成 `agent/`、`repo/`、`pkg/`，记忆的提交与提取拆成有名字的阶段。这一阶段的成果是一个能编译、只在作者自己的参考应用里跑过的库：没有 tag，也没有桌面端。

## 二、收成一条事件循环（10-24 – 10-25）

**27 个提交**：10-24 十三个，10-25 十四个。

10-24 先修一批安全、脱敏与编排的错误（`aec429e`、`ee05459`），再把「谁拥有什么」写进代码：`58221f1` 让每个核心概念只有一个所有者，工作区操作从网关移进 agent；`268a420` 把轮次队列压成一次幂等的 settle；同一天 `4106bd3` 把 orchestrator 的锁换成单个事件循环。

10-25 压平结构：`49d2287` 给 agent 加薄门面，同一天的 `7ba0f36` 又把 orchestrator 折进 agent、删掉这层转发——门面当天就被删掉。留下的是 `0fae87a`（调度收敛成一次 reconcile）、`026aa38`（提示词前缀跨轮稳定）、`218f30f`（把「没跑过」和「跑到一半被截断」分开）。此后引擎是常驻进程里的调度器，不再是一组可随意调用的函数。

## 三、槽位调度与协议契约（10-26 – 10-27）

**24 个提交**：10-26 十六个，10-27 八个。

10-26 定型并发：`23cac37` 用共享槽位限制同时执行的一轮，顶层会话排在子 agent 前；`530e97c` 让等槽位的会话从数据库读，不在内存排队；`4daf0e8` 让 admit 每个事件只跑一次、自己 reconcile 每个候选。同一天 `c85e08f` 把网关消息声明在一张表里，`go generate` 从表写出 `gateway/protocol.schema.json`，`initialize` 回报契约的 sha256。

10-27 转向外部世界与上下文：`2ad6af5` 让 MCP 经 stdio 或 HTTP 接入并各自报状态，`e5dbf12` 把记忆改成每会话加载一次、压缩后刷新，`cce6f5f` 把记忆分成三层作用域。产物是「一个进程 + 一份库 + 一份可校验的契约」：界面还没出现，形状已经定好。

## 四、从库到框架（10-28 – 10-29）

**22 个提交**：10-28 十六个，10-29 六个。

10-28 是文档、许可与版本号的一天。`d522016` 删掉没人用的导出与 `docs/` 下的长文，README 改成只列区别点；`a52677b` 再改成围绕共享执行池来写，许可切到 MIT。`be273dd` 要求每条模型连接声明上下文限额、删掉内置限额表，`v0.1.0` 打在这里——距首个提交 11 天。`cfb0ce2` 与 `8a7a0e7` 让审批可以「总是允许」，执行前重新核对批准的内容。

10-29 都在提示词层：`0322ce5` 让每个 agent 带完整规则并保持前缀可缓存，`3205976` 在工具装不下时改为延迟加载。此后对外的说法从「一个库」变成「一个框架」，也有了第一个可引用的版本。

## 五、工具面、持久化与基准（10-30 – 11-04）

**29 个提交**：10-30 五个，10-31 两个，11-01 五个，11-02 十个，11-03 五个，11-04 两个。

`287d0ed`（10-30）把一批功能合进一条提交：会话重命名、归档、删除，`edit_file`、`write_file` 带冻结 diff，消息可带图片与附件，`search` 覆盖会话、消息、任务与记忆，`pkg/llm` 增加原生 Anthropic 与 Gemini 客户端，`web_fetch` 只连公网地址。

11-01 两件事改变长期形态：`a27cc8f` 用编号 migration 取代 AutoMigrate（库里开始有用户的真实对话），`6376672` 把定位改成「给云服务商构建大规模并发的个人 agent 服务」。11-02 到 11-04 重心转到测量：`bf0e471`、`be14c61` 加突发与崩溃实验，`18f5459` 用基准数字支撑 README，`cc4737d` 把 pi 与 DeepSeek Harness 放进同一份负载对照，`91b83c8` 在空闲机器上重跑；`5b34df7` 把三个客户端的重试统一成 8 次退避。

这一阶段把引擎从「能跑」推到「能证明」：schema 版本、九个基准实验、外部对照。

## 六、多用户、分片与沙箱（11-05 – 11-07）

**17 个提交**：11-05 十个，11-06 两个，11-07 五个。

11-05 一天内完成从单用户到多用户，是全部历史里最集中的架构改动：`4b549e1` 让一个数据库成为一个分片，工作区、会话、记忆都带 user 列；`477f8f7`、`1ff8637` 给每个用户自己的连接、事件与槽位上限；`0e7688f` 给分片加租约，备用进程可以接管；`30f586b` 把命令、文件、MCP 从直接操作本机改成走 `sandbox.Box`；`af8624c` 补上「一个用户的故障不能波及整个分片」，并把 token 从 URL 移到 WebSocket 子协议。

11-06 到 11-07 收拾边界：`805708f` 把 README 与图表改成英文；`87d2b9f`、`b2834b4`、`9f75884` 处理输入预算小的模型（可声明比窗口更小的输入上限，输出不再被输入吃光，小模型走精简提示词）；`84ef1b5` 允许 never 策略把命令放行到沙箱外；`62902ed` 停止在沙箱里关掉 `.git`。`v0.11.2` 打在最后一个提交上。

## 八、角色、逐步运行与包结构（11-13 – 11-16）

**100 个提交**（含 3 个合并）：11-13 一个，11-14 五十六个，11-15 三十四个，11-16 九个。11-14 是全部历史上提交最多的一天。

11-16 的 `f87d65a` 给每个角色自己的运行，同时去掉后台调用和追踪——追踪从 `b1f7285` 起只存在了三天。合并 `d4f6d29` 打出 `v0.14.0`；`6ecaaea` 让一轮按条目一步步运行、每步之后重读条目和权限，合并 `1bf4ba5` 打出 `v0.15.0`；`v0.15.0` 把 cron 挪到顶层，`v0.15.1` 又把它挪回工具下面。

## 九、以对话日志重建（11-16 – 11-17）

**56 个提交**（含 10 个合并）：11-16 两个，11-17 五十四个。

11-17 上午还在旧结构上收拾：`5e5dbc4`（11-16）让一次运行的权限由部署允许的范围算出，`bb13d13` 让引擎不再输出运行日志，`3580e6f` 把每个用户的 MCP 服务器、权限层和记忆开关存进库，`806a975` 让网关不碰存储、只听事件总线；`68a4035` 用一个 `shard` 包把进程当作分片来跑，引擎本身不知道分片，`8874aa2` 把目录放到接口后面、租约按目录自己的时钟判定。

随后是重建本身，一个包一个提交：`9b2c378` 加入 `conversation`——会话是一份只追加的日志，轮次和条目从它折叠出来；`abad1b8` 的 `policy` 把权限判定写成纯函数；`4765533` 的 `agent` 从日志读出下一步；`e3aa45f`、`87702d3` 的 `store` 把会话存成日志，提交后按序号发到 feed；`b7b6bdf` 的 `run` 一步一步跑一轮，`82081ec` 的 `schedule` 从 feed 得知谁可以运行；`b9b330f` 的 `app` 让用户的每个操作都是一次检查加一个事务；`499f96f` 把网关建在 `app` 和 feed 上，`9fa9186` 加 `host` 负责装配，`41b50d8` 让基准也经 `host` 跑；最后 `619e2e6` 删掉旧引擎。合并 `25321d6` 打出 `v0.16.0`：协议的通知全换，新库 `data/store.sqlite` 不从旧库迁移，tag 说明写明基准数字早于这次重建、要重测。

## 十、补齐与整理（11-18）

## 双仓库的节奏与现状

### 桌面端如何跟随引擎

本节桌面端的数字统计到 2026-11-08，之后没有重新核对；引擎的数字统计到 `v0.17.1`。

桌面端从 `desktop@563a633`（10-25）开始，比引擎首个提交晚 8 天，首个提交 99 个文件、10,573 行，一开始就是 Electron + React 加一个 Go sidecar。

引擎是库不是程序，绑定点只有一个：`sidecar/go.mod`。它被改过 16 次，钉过的引擎版本依次是 `v0.0.0`（`replace ../../ollupi`）、`v0.1.0`、`v0.2.0`、`v0.3.0`、`v0.5.0`、`v0.6.0`、`v0.7.0`、`v0.8.0`、`v0.8.1`、`v0.8.2`、`v0.8.3`、`v0.9.0`、`v0.10.2`、`v0.10.3`、`v0.10.4`、`v0.11.2`。其中 12 个提交以「Run on ollupi vX」命名，做的是同一件事：升依赖、重新生成 `packages/protocol/src/generated/` 的契约、把界面改到新形状上；`packages/protocol` 被 28 个提交碰过。

跟得不整齐：到 11-08 引擎打了 23 个 tag，sidecar 钉过其中 15 个，`v0.3.1`、`v0.4.0`、`v0.8.4`、`v0.8.5`、`v0.10.0`、`v0.10.1`、`v0.11.0`、`v0.11.1` 都没跟。桌面端按功能批次升，不按每个 tag 升。

版本号各自独立：11-08 时引擎是 `v0.11.2`，桌面是 `0.7.24`。两边同一天（10-28）各自打了 `0.1.0`，之后不再对齐，唯一的事实来源是 `sidecar/go.mod` 里那一行。桌面端在 10-28 到 11-08 之间发了 28 个版本。

节奏上有两段空档：11-03、11-04 桌面端没有提交，引擎这几天只提交基准与重试；反过来 11-08 只有桌面端有 15 个提交，引擎停在 11-07。10-27、10-28、11-01、11-02、11-08 是桌面端的密集日（26、31、23、17、15 个提交），设置页、设计 token、渲染与浏览器面板都在这些天定型。

一次事故来自这个绑定：`0.7.8` 通过本地 `go.work` 带上了未发布的引擎，界面没有对应契约，`desktop@93d828f`（11-02）之后发版构建改用 `GOWORK=off`，见 [决策 11](/zh/reference/decisions#_11-sidecar-形态)。

### 取数方法

以下命令在各自仓库根目录执行，本文每个数字都来自它们：

```sh
git rev-list --count HEAD                                          # 提交总数
git log --date=short --pretty=format:'%h %ad %s'                   # 时间线
git log --date=short --pretty=format:'%ad' | sort | uniq -c         # 每天多少提交
git tag --sort=creatordate                                         # 引擎的版本只有 tag
node -p "require('./apps/desktop/package.json').version"          # 桌面端版本
git ls-files '*.go' | wc -l && git ls-files '*.go' | xargs wc -l | tail -1
git log -p --date=short --pretty=format:'COMMIT %h %ad' -- sidecar/go.mod
git log --pretty=format:'%s' | grep 'Run on ollupi'
```

两处易读错：`git log | wc -l` 比实际少 1（最后一行没有换行），计数用 `git rev-list --count`；`git show --stat` 的行数是那次提交的增删，不是现在的规模。
