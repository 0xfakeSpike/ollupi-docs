# Ollupi 功能清单

覆盖 ollupi（Go 引擎库）和 ollupi-desktop（macOS 桌面端 + sidecar 后端）。标注：〔引擎〕ollupi 提供，〔桌面〕desktop 提供。

## 1. 执行与调度〔引擎〕

- 共享执行池
  - 所有会话、子 agent、定时任务的 turn 进同一个队列
  - 槽位并发（默认 32），等审批 / 等回答 / 等子 agent 或后台任务时让出槽位
  - 按模型连接限并发（默认每连接 4 个），工具执行不占名额
  - 优先级：普通会话先于子 agent，同类先到先走
- 后台任务单独一个队列，和 turn 分开：槽位 32，每个用户最多 4 个，先到先跑，每个最长 1 小时
- 持久化与恢复
  - 会话是一份只追加的日志，轮次和条目都从日志折叠出来；每一步先追加日志再执行，追加前检查它能不能接在后面，不能就整笔拒绝
  - 一切变化在提交后发到 feed，网关、调度器、记忆提炼都从 feed 得知；同一次提交的变化共用一个序号
  - 表结构按编号的 migration 升级，库里记版本号
  - 第一次打开时，若新库还没有用户、旁边有旧引擎的 `data/ollupi.sqlite`，就把它整份导入成会话日志：用户、设置、环境、工作区、MCP 服务器、定时任务和记忆保留原 id，每轮的审批、提问、子 agent 派生都还原；旧引擎没结束的轮记为被升级中断，不会重跑；旧文件原样保留，导入失败不写任何东西，下次再试
  - 进程重启后可运行的会话接着跑；已开始未结束的调用记为被切断，agent 被提示先核实再重试，不会自动执行两次
- 多用户与分片
  - 一个库是一个分片，用户共用它的表；工作区、会话、记忆、设置按用户分开，别人的东西一律当不存在
  - 网关按令牌认出用户，事件只发给本人；每个用户最多四条连接（一台设备一条），每条都收到本人的全部事件，第五条顶掉最早的那条；可限制单个用户占用的槽位，可给每个用户配自己的模型客户端
  - 客户端只连一个地址：负载均衡器经外部处理回调问出分片，或由路由器转发，把连接送到用户所在的分片；新用户在随机抽出的两个接收新用户的分片里，放到报告负载较轻的那个
  - 长连接：每 30 秒心跳，网关一直等着读却 15 秒没收到回应就断开，因入站限速或积压暂停读取时不算；连接在打开后 15 到 20 小时之间的随机时刻关闭重连；新连接限速接纳，超出时回 503 和 `Retry-After`
  - 分片租约：同一时间一个进程持有分片，进程死后备用进程接管，失去租约的进程写不进库
  - 〔桌面〕只有一个用户：桌面和飞书都以默认用户运行
- 出错即暴露：一轮运行出错或超过时限（默认四小时）时以失败结束并写明原因；连失败都记不下时调度器停下，把错误交给宿主；部署的权限设置读不懂时宿主拒绝启动

## 2. 会话（Thread / Turn）

- 会话管理〔引擎〕
  - 新建、分页列出（按更新时间，游标翻页）、分页读取、恢复会话
  - 会话归属工作区，或不属于任何工作区（general）
  - 环境（environment）：新建时选定在哪个环境跑命令和读写文件，之后不变；子 agent 会话跟随父会话；未指定时用本机环境
  - 标题：新建时由界面给出，或重命名；子 agent 会话取任务描述
  - 归档 / 恢复：归档后不收新消息，定时任务不发送；有进行中的轮次时拒绝
  - 删除：连同子 agent 会话、附件和定时任务
  - 已读状态：记下每轮结束的时间（`repliedAt`）和用户读到的时间（`readAt`，`thread/markRead`），前者更晚即为未读；升级时已有的会话都算已读
  - 变化通知：会话、轮次、条目各一种，带着改它的那次提交的序号；读一页时也给出读到的序号，客户端丢掉不比它新的通知
  - 会话状态：空闲、在跑、等审批、等回答；子 agent 在等用户时父会话也算在等（审批优先）
- 一轮对话〔引擎〕
  - 开始、插话（steer：消息加进当前轮次，agent 下一步就读到，在等的审批和提问随之作废；插话到达时还在生成的那次回答不记入日志，agent 带着这条消息重新回答，〔桌面〕已经流式显示出来的那段随之消失）、中断
  - 排队：有一轮在跑时发的消息各自成为排在后面的一轮，最多排 20 轮
  - 工具调用：同一次回答要的调用依次判定、执行，连在一起的只读调用一起跑（最多 8 个）；一轮最多 400 次工具调用、200 次模型调用（压缩用的那次不算），用户拒绝一次调用或连续 10 次调用失败后停用工具，让 agent 收尾
  - 模型文本与思考过程流式输出；回复保存时整条写入；思考从第一段流式内容记到开始回答（不流式的模型从发出请求记到收到回复）
  - 附件：按本机路径发送图片（PNG / JPEG / GIF / WebP）和文本文件，按内容判断类型，每条最多 10 个；发送时复制进数据目录下的附件存储，复制中文件变了就拒绝；不支持图片的模型拒绝而不丢弃
- 上下文管理〔引擎〕
  - 按模型的上下文和最大输入装入窗口，为回答预留输出上限和窗口四分之一里较小的
  - 要声明回答上限的 API（Anthropic、Gemini），按当次输入收紧到窗口放得下的长度
  - 输入预算不足 16384 token 的模型自动用精简版：短提示词、精简版自己的技能，只发 `read_file`、`run_command`、`load_tools`，其余工具只列名字，用到时加载
  - 超过阈值自动压缩，保留最近用户消息和工具产物
  - 工具输出过长时截断，可用 `read_tool_output` 分段读回
  - 系统提示词前缀保持稳定，利于服务商前缀缓存
- 会话界面〔桌面〕
  - 新会话：侧边栏顶部的"新的事"或 ⌘N；⌘K 打开搜索
  - 草稿页：问候"有什么可以交给我？"和所在文件夹的名字，选环境、工作区和模型后输入第一条任务，标题取第一条消息的开头
    - 可以从这些开始：问候下面最多四张卡片（窄窗口两张），来自选了的文件夹、装了的一个技能、定时任务、浏览器和记忆；点一下把这件事写进输入框，改了再发；输入框里有内容时不显示
    - 环境选择里本机显示为"这台电脑"（随界面语言）
  - 环境：草稿页选新会话在哪个环境里跑——这台电脑，或自己命名的云端沙箱，选择记到下一次；选择器里的"管理环境…"可新增、重命名、删除（这台电脑不能删，有会话在用的也不能删）；在云端环境里开始的会话在标题栏显示它的名字，草稿页也会说明这一版只在这台电脑上跑命令、在云端环境里开始的会话会被拒绝
  - 侧边栏是一张导览图：每个工作区是一块有自己颜色的区域（六种低饱和色，按工作区固定分配），区域标题写名字和"· N 件"，有等你的会话时加"N 件等你"；悬停区域标题出现"在这里开新的事"和"…"菜单；会话行尾按优先级显示"等你"、"在做"、未读圆点或相对时间；等你的会话滚出列表视野时，列表下方出现"N 件等你"，点一下滚到它
  - 侧边栏：悬停会话行出现归档和"更多"，重命名、删除在"更多"菜单里，右键会话行也能打开这个菜单，双击也能重命名；已归档会话列表，可恢复或删除；会话多时加载更多
    - 等你审批或回答的会话排在所在分组最前，有这种会话的工作区排在其他工作区前面；处理完回到原来的位置
    - 其余按最近活动排：组内的会话最新的在上，工作区按组里最新会话的时间（或工作区自己最近一次改动）排
    - 未读：一轮结束后你还没看的会话显示实心圆点、标题加深；打开它（窗口在前台时）就算已读，已读状态存在引擎里，各客户端一致
  - 标题栏：左边是带工作区颜色的区域标签和标题，点标题重命名，标题先截断；有卡片在等你时右边显示"N 件等你"；浏览器、文件两个常用面板各有按钮，其余面板（环境、终端、任务、上下文）和导出收在"更多"里：鼠标停在按钮上就展开（点击、↓ / ↵ 也能打开），面板两两一行排成方块，图标和名称一行、下面一行小字说明，导出在细线下面一行，离按钮都不远；开着的面板的按钮显示为苔色，窗口窄时只留图标；已归档的会话显示提示和恢复按钮
  - 时间线：消息、附件、思考（含耗时）、工具调用、压缩 / 记忆加载提示，加载更早消息
    - 结果在前：一轮按"你的话 → 回答 → 改动的文件 → 过程"排，过程放在回答后面；这一轮写入的文件在回答下面列成文件卡片（文件名、所在文件夹、打开）；工作区里的文件点卡片在文件面板打开，"打开"交给系统默认应用，没选工作区的会话写在 `~/.ollupi/scratch` 的文件也能打开
    - 时间：用户消息气泡下方是发送时间，回答下面那行打头是这一轮结束的时间（今天只写钟点，昨天写"昨天"，更早带日期），悬停看完整日期
    - 复制：悬停用户消息时气泡旁出现复制按钮；一轮结束后，回答下面那行的其余部分（复制回答、模型、时长、用量）只在指向或聚焦这一轮时出现；时长从这一轮开始跑算起（排在后面的从前一轮结束算起）
    - 编辑：最新一条用户消息悬停时还有编辑按钮，点了停止正在跑的一轮，把这条消息的文字和附件放回输入框重新编辑（输入框里已有的字保留在后面）；原消息留在历史里，再发出是一条新消息
    - 一轮分成过程和回答：按模型调用（`responseId`）区分，要了工具的那次调用是过程，没要工具的那次的文字是回答；过程里的说明文字用小一号的淡色
    - 运行中过程逐步展开；一轮结束后过程收成一句人话"想了 25 秒，看了 9 个文件，运行了 6 条命令，1 项失败"，点开看全部步骤；没有回答时（如失败）保持展开；插话把过程分成前后两段
    - 最后一轮失败时，错误旁有"重试"，把这一轮收到的消息（文字和附件）合成一条再发一轮
    - 会话还没有消息时显示说明
  - 排队的消息：排在当前轮后面的每一轮，用虚线气泡列出它的消息，标"排队中"
  - 读文件和搜索：读取显示内容和行范围（文件太大没数完时写"至少 N 行"），查找显示文件列表，搜索按文件列出命中行及上下文；连在一起的几次合成一行（"读了 3 个文件，搜索 2 次"），可展开；结果里的路径点一下在"文件"面板打开，⌘+点击用默认应用打开
  - 状态行：一轮运行时输入框上方一个缓慢呼吸的圆点，写着"它在做"；等你批准或回答时换成醒目的圆点，写着"等你在上方点个头" / "等你在上方回答一下"；只等后台任务时写"后台任务在跑，跑完它接着回你"，子 agent 和后台任务都在等时写"子 agent 和后台任务在做，做完它接着回你"
  - 后台跑的调用：调用行标"在后台"，交回报告前显示在跑，交回后显示报告里的结果（命令的输出和退出码），失败、被停下或中断时标失败；报告到达处单独一行"后台任务结束：<命令或工具>"
  - 输入框：发送、插话（Enter）、排队（Alt+Enter）、停止当前轮（停止按钮或 Esc，没有卡片在等你时）；没发出去的文字和附件按会话各自留着，切到别的会话或开新会话再回来还在；重载界面后文字还在，附件不保留；会话删除后清掉
  - 附件：粘贴、拖入或选择图片和文件，发送前预览；粘贴的截图这类没有路径的文件，发送时先写成临时文件，发完即删；时间线里点开看大图或文本
  - 模型选择器：输入框里只显示模型名（窄窗口只剩图标）；浮层菜单按服务商分组，模型多时可查找，标出默认模型和不可用的模型
  - 审批策略标签：输入框里带盾牌显示这个会话生效的审批策略，三档写成"什么都先问我 / 要紧的先问我 / 放手去做"（严格 / 适中 / 宽松），"放手去做"用警告色；菜单里每一档写着它放行什么，可改成会话自己的一档，或回到跟随工作区 / agent 默认，最后一项打开这个会话的权限规则；新会话页选的策略在开始会话时带上
  - Markdown 渲染：代码高亮（shiki）、复制、Mermaid 图、脚注；中文里的裸链接到第一个中文字符或全角标点为止，不把后面的句子算进链接
  - 只画看得见的部分：代码高亮和 Mermaid 图在滚到附近时才画，流式输出中的代码块写完才高亮
  - 回复里提到的工作区文件（行内代码或链接，确认存在后）可点击：单击在"文件"面板打开，⌘+点击用默认应用打开
  - 每轮用量：输入 / 缓存 / 写入缓存 / 输出 token
  - 标注由哪个定时任务发送的消息
  - 导出：Markdown，或含全部条目的 JSON，保存到自选位置
  - 自动滚到底 / 回到最新

## 3. 会话侧边面板〔桌面〕

- 面板停靠在窗口右侧，整列高度，和对话以分隔线并排；标题栏与对话标题栏对齐，可拖动窗口
- 草稿页也能打开面板：浏览器随时可开；文件、环境、终端在选了工作区后可开
- 拖动面板左边缘调整宽度（也可用方向键），每个面板记住自己的宽度，双击边缘恢复默认；给对话至少留 360px，窗口太窄放不下时面板从右边盖在对话上
- 浏览器：每个会话有自己的一组标签页，agent 和用户共用，agent 在当前显示的标签页里操作；草稿页打开的标签页在发出第一条消息后归这个会话；新建、切换、关闭标签页，网页打开新窗口时开成新标签页（只开 http 和 https 网页）；地址栏、前进、后退、刷新，用户可随时接手
  - 起始页：打开浏览器时这个会话还没有标签页，就新开一个进入 Google；点"+"新建的标签页也进入 Google（agent 打开的标签页直接去它要的网址）
  - 地址栏搜索：输入的是网址（带协议，或像 example.com、localhost:3000、IP 这样的地址）就直接打开，其余（含空格的词、单个词）用 Google 搜索
  - 归档或删除会话时关掉它的标签页：每个标签页都是一个常驻的网页，没人再看就不再留着占内存
  - 收藏：地址栏星标收藏当前页，收藏列表可筛选，点击在当前标签页打开；同时列出本机各 Chrome 个人资料的收藏（只读）
  - 历史记录：记下每个标签页打开过的网页（用户和 agent 打开的都算），每个网页记访问次数和最近访问时间，最多保留 5000 个；地址栏的历史按钮打开列表，按最近访问排在前面，显示标题、网站和时间，可搜索（标题和地址都匹配），点击在当前标签页打开，可逐条删除或清除全部；设置 → 通用里也可清除
  - 地址栏补全：输入时列出匹配的历史和收藏（含 Chrome 收藏），地址开头匹配的排前面，再按访问次数和最近访问排序；最匹配的地址直接补进输入框（还在输入网站名时只补到网站）；方向键选择，回车打开，Esc 收起
  - 下载：网页要下载文件时弹出系统保存对话框，默认存到「下载」；保存后浏览器面板顶部显示保存路径，可就地在访达中显示；关掉对话框就不存，面板也不留提示
  - 登录状态长期保存在应用自己的浏览器数据里（`~/Library/Application Support/Ollupi/Partitions/browser`），不和 Chrome 共用；对网站报的是 Chrome 的 User-Agent
- 文件：浏览工作区文件，预览文本（大文件只显示开头）
  - 打开的文件可在访达中显示；文件列表里右键文件或文件夹，可选"在访达中显示"
  - Markdown 默认渲染显示，可切换查看源码，切换后对之后打开的文件保持；文中相对路径的图片和链接按该文件所在文件夹解析：图片从工作区读出显示，读不到时显示图片说明，链接到工作区文件时点击在文件面板打开
  - PDF 用 Chromium 自带的阅读器显示，可翻页、缩放、搜索（50 MB 以内）
  - 打开的文件上方显示从工作区起的路径，可复制完整路径
  - 路径里的文件夹：单击列出其中文件，可展开子文件夹并跳到别的文件；双击回到文件列表并展开、定位到该文件夹
- 环境（分支图标）：先写"改了 N 个文件"（不是 git 仓库时说明没有版本记录），看 diff 时隐藏位置信息
  - 位置：一行"这台电脑上的「某」文件夹"，点开看运行命令的环境（本机或云端沙箱；草稿页为选中的环境）、工作区目录（点击在访达中显示）、git 分支（不在分支上时显示所在提交）
  - 改动：工作区相对上次 git 提交的改动列表（修改 / 新增 / 删除 / 未跟踪）和逐文件 diff
    - 暂存 / 取消暂存（单个或全部），标出部分暂存
    - 丢弃改动（先确认）：回到上次提交的样子；没有提交过的文件移到废纸篓
    - 填写提交信息，提交已暂存的文件（⌘Enter）
- 终端：每个工作区一个登录 shell，在工作区目录打开；用户自己的 shell，不经过 agent 和沙箱；关闭面板后继续运行，可新开；颜色按浅色、深色各配一套，切换外观时跟着换；拖选后 ⌘C 复制，程序占着鼠标时（vim、less、TUI）按住 Option 拖选
- 任务：agent 当前的计划与进度（已完成 n/m）
- 上下文：先用一句话说还宽裕 / 快满了 / 满了，用了多少、到多少时会自动压缩（不用你管），一条进度和带着几条记忆；"细节"里是系统提示词 / 工具定义 / 消息 / 记忆占比，最近调用的缓存命中，每次模型调用列表（只写模型名）
- 会话权限：会话级审批策略和规则；从输入框的审批策略菜单打开

## 4. 搜索

- 〔引擎〕`search`：一次查询，按类别返回会话（标题）、消息（用户消息和回复正文，带片段）、定时任务、记忆；多个词都要命中，可限定工作区；查询最多 200 个字符、8 个词（写在协议契约里），超过 5 秒回超时错误
- 〔桌面〕
  - 侧边栏"搜索"（⌘K），分组展示结果并标出命中的词，可限定工作区；超过后端上限（字符数和词数，取自协议契约）的查询不发出去，和超时一样在结果处说明，不弹通知
  - 点结果直接定位：消息定位到会话中的那一条，定时任务和记忆定位到所在页面的那一条
  - 记忆页的搜索框

## 5. 子 agent

- 〔引擎〕`general-sub-agent`、`browser-sub-agent` 工具派生子 agent，子 agent 是普通会话和 turn；派生立即返回，子 agent 和父会话同时跑，结束时把报告写回派生它的那一轮；父会话答完后等它的子 agent 都交回报告再接着回答，期间发来的消息让它先回话；子 agent 在等审批或回答时，父会话的状态也算在等（审批优先），侧边栏、角标和"N 件等你"都算上它
- 〔桌面〕派生子 agent 的调用行显示任务，子 agent 在等你审批或回答时卡片显示在这一行下面，没交回报告时标"子 agent 处理中"，浏览器子 agent 用地球图标并标明"在浏览器里"；报告单独一行显示，失败时标出；这一轮没有别的事在做、只等子 agent 时，输入框上方写"子 agent 在做，做完它接着回你"；可打开子 agent 会话、返回父会话；汇报的子 agent 会话只读，经父会话沟通
- 〔引擎〕委派：`delegate-sub-agent` 把一件事整个交出去，不汇报，父轮次不等它、结束时也不停它；委派会话是用户自己的会话，出现在会话列表和搜索里，有未读标记，可以直接回复；它不能再派生子 agent、不能建定时任务；父会话还有委派会话时不能删除
- 〔桌面〕委派的调用行标"已委派"，不显示"处理中"、不把它的等待算进父会话；委派会话在侧边栏列在它的工作区里，标题旁标"委派"，可以改名、回复，返回箭头回到交出它的会话；删除还有委派会话的会话时说明要先删掉那些会话


## 6. Super Agent（中枢）

- 〔引擎〕中枢工作区：工作区分项目和中枢两种，一个用户最多一个中枢；部署打开中枢才有（〔桌面〕已打开）
  - 中枢里的会话以 `hub-main-agent` 运行：不做项目里的活，按计划把事情交给各个项目，用户问起时去查进展、检查后再说做完；不能派生子 agent、不能用浏览器
  - 中枢工具：列出工作区；在项目工作区里开新会话并发出第一条消息、给项目里的会话发消息（和用户自己发的一样，按那个工作区的权限跑）；消息记下是哪个中枢会话代发的，正文不加标记，模型看到的消息头注明代发；查看各会话的状态、排队的轮次、最后一轮怎样结束、是否已读和最后回答的开头；读一个会话最近几轮的消息
  - 计划：中枢自己用文件工具记在它的文件夹里，引擎不存待办
    - `TODO.md` 只放没结束的事，每件一行：`- [ ] 做什么 · 项目 · [会话标题](#thread-<会话 id>)`，交出去之前不写项目和链接
    - 做完或不做的从 `TODO.md` 移到 `done/<年>-<月>.md`（按结束的月份）：做完标 `[x]` 写一句结果，不做的标 `[x]`、任务加删除线并写原因；这些文件只在用户问起以前的事时才读，所以 `TODO.md` 一直短
- 〔桌面〕
  - 侧边栏最上面一块是 Super Agent：还没有时写一句它是什么和"开始"，点了在后端目录里建好它的文件夹、设成中枢、打开新会话；有了以后列出它的会话，标题后写还有几条待办（`TODO.md` 里没勾掉的项）
  - 新会话页换成"有哪些事要办？"和一句它怎么做，不显示起步建议
  - 对话里：开会话写"在「项目」开了一件事：标题"，展开见发出的消息和"打开会话"；发消息写"给「会话」发了消息"；查看进展是一行"看了各件事的进展"；写计划是普通的文件改动；过程摘要先写"交出了 N 件事"
  - 待办面板：标题栏第一个胶囊；把 `TODO.md` 按行解析后画成列表，分"未分派"和"进行中"并标数量；每件事两行：任务和它的会话状态（等你 / 在做 / 未读）、打开会话的按钮，下面是项目标签（工作区的颜色）和备注；"归档"按月份列出做完和放弃的（每月一个胶囊，点开用同样的列表，放弃的划掉）；解析不出的内容收进"其他内容"原样显示；重新读取、打开文件在标题栏；打开面板、窗口回到前台、任何会话写完这些文件时重新读取
  - 项目会话里，Super Agent 代发的消息上方写"Super Agent 代你发来 · 会话标题"，点了回到那个会话
  - 设置只有指令和权限（名字和文件夹由应用管）；能力页里 Super Agent 和委派各有自己的技能

## 7. 审批与提问

- 审批〔引擎〕
  - 工具调用请求审批，决定：允许一次 / 在此会话中允许 / 拒绝
  - 建议的规则：命令按程序或子命令（`tail:*`、`git status:*`），敏感命令（`rm`、`sudo`、解释器、`git push` 等）只建议它本身；web_fetch 按域名；需要完全访问的调用也有建议，只是交给 shell 或解释器执行的部分（`curl … | bash`）没有
  - 在此会话中允许：这个会话里，建议规则覆盖到的后续调用都不再问（不只是同一个调用）；需要完全访问的调用只覆盖同样需要完全访问的
  - 总是允许：把建议的规则写入工作区、会话或上级会话，界面的权限设置随即更新；需要完全访问的调用写进"完全访问也允许"（escalate），以后这类调用以完全访问直接运行
  - 审批前冻结目录、命令和环境变量，执行时校验仍与批准内容一致
- 结构化提问〔引擎〕：`request_user_input`，回答成为工具结果；也可以跳过，这次调用记为拒绝，agent 不带答案继续
- 界面〔桌面〕
  - 审批卡片：一块醒目的底色，标题是问题，下面是要做的事（命令、文件）和一句后果（"在「某某」文件夹里运行。"、只改这一个文件；完全访问写明它能碰到什么）；命令所在文件夹、diff、理由和"以后…都可以"收在"看细节"里
    - 三个答案：先不要（Esc）/ 这件事里都可以 / 可以（↵）；出现时焦点落在"可以"上并滚进视野（需要完全访问时落在"先不要"上），输入框里正在打字时不抢焦点；完全访问只能点按钮允许
    - 卡片滚出视野时，输入框上方出现"N 个请求在等你"，点一下滚回卡片
    - 处理过的调用在行尾标出"你同意了 / 这件事里都可以 / 以后都可以 / 已拒绝"
    - 需要完全访问的调用，"以后…都可以"写成"以后在「某某」里完全访问也都可以"，细节里写明会添加到"完全访问也允许"
  - 提问卡片：选项或自填回答，多题进度；回答被引擎拒绝时提示原因；"跳过"不回答直接让 agent 继续
  - 侧边栏标出"等待你处理"的会话

## 8. 权限与安全〔引擎〕

- 审批策略：严格（untrusted）/ 适中（on-request）/ 宽松（never）
  - 严格：只有不改动、不联网的读取直接执行，其他都先问
  - 适中：读取和在限制内的命令直接执行；限制外的改动、需要完全访问的命令先问
  - 宽松：规则以外一律直接执行，需要完全访问的命令也不例外
- 规则：allow / escalate / ask / deny，如 `run_command(git:*)`
  - escalate（完全访问也允许）：匹配的调用即使需要完全访问也不问，也包含 allow 的范围；deny 和 ask 先判定
  - deny 与 ask 在三档下都算数：宽松下禁止仍然禁止，询问仍然先问；复杂到无法对照规则检查的命令，宽松下遇到禁止规则直接拒绝，遇到询问规则仍然先问
  - 部署、用户、工作区、会话四层叠加，下层去不掉上层的 deny；用户这层存在引擎里，随时可改，从下一次调用起生效
  - 〔桌面〕部署这层只定默认的审批策略为适中；设置 → 权限编辑用户这层；工作区和会话的权限里四类规则各一栏（总是允许 / 完全访问也允许 / 总是先问我 / 禁止）
  - 命令按程序名和参数结构化匹配，拆开 `sh -c`、`env`、`xargs`、`sudo` 等包装；`sh -c` 的脚本按 shell 语法解析，子 shell 和复合语句里的命令逐个匹配，这样的调用仍然先问
  - 看不清的命令（变量、`$(...)`）不自动放行
- macOS Seatbelt 沙箱
  - 模式：只读 / 工作区可写 / 完全访问
  - 凭据文件不可读，缓存只读；`.git`（含 config 与 hooks）可写，但会随后被程序执行的设置文件（`.envrc`、`.husky`、`.pre-commit-config.yaml`、`.vscode`、shell rc 等）不可写
  - 网络走代理，只放行允许的域名，拦截解析到内网的地址
  - 命令结束时清理派生的后台进程，报告沙箱拒绝原因（几乎所有进程都会碰到、不影响结果的 `/dev/dtracehelper`、`/dev/tty` 不报）
  - 默认可写的缓存：npm（`~/.npm/_cacache`、`_logs`）和 Go 的编译缓存（`~/Library/Caches/go-build`）
  - 命令可申请完全访问（提权，解除 Seatbelt 限制）：严格、适中下单独批准，宽松下不问直接运行；审批里只显示 agent 给的理由
- 命令和文件都经沙箱接口，每个用户可以有自己的沙箱：本机 Seatbelt，或接入云沙箱（命令受限，不能提权）
- 环境〔引擎〕：每个用户一份环境列表，一个固定是本机，其余是自建的云沙箱
  - 新建会话时指定环境；会话记住它，子 agent 会话跟随父会话；被会话占用的环境不能删，本机环境不能删
  - 〔桌面〕草稿页可选环境，可新增、重命名、删除云沙箱；命令只在本机跑，在云沙箱里开始的会话，命令会被明确拒绝而不是在本机跑
- 双向脱敏
  - 识别手机号、邮箱、身份证、银行卡、IP、MAC、JWT、密钥
  - 发给模型前换成 HMAC 占位符，回答在记录和交给工具前还原
  - 可随时开关〔桌面：设置 → 脱敏〕

## 9. 工作区

- 〔引擎〕添加、重命名、移动文件夹、归档；工作区级权限
  - 指令：一段话（最多两万字），这个工作区里每个会话、每个角色的系统提示词都带上它
  - 工具来源：按工作区打开或关掉某些 provider 的工具；部署可以把一些 provider 设成只在打开它们的工作区里出现
  - 子 agent 和父会话在同一个工作区里
  - 移动文件夹：把工作区自己的文件夹搬到另一个位置（选中的文件夹须存在且为空），工作区 ID 不变，会话、记忆和定时任务照旧；有轮次在跑时拒绝
- 〔桌面〕
  - 侧边栏按工作区分组会话，展开更多 / 收起
  - 在 Finder 中打开文件夹、在工作区中新建会话
  - 工作区设置：名称、文件夹（显示路径，可移动到别处）、指令（失焦保存）、权限
  - 已归档工作区列表与恢复

## 10. 工具与能力

- 内置工具〔引擎〕
  - `update_plan`、`request_user_input`、`read_tool_output`、`memory_search`、`load_tools`；派生子 agent 的工具见第 5 节
  - `claude`：把一件事交给调用者沙箱里的 Claude Code
  - 技能：`list_skills`、`activate_skill`、`read_skill_resource`
  - 定时任务：`create_` / `pause_` / `delete_` / `list_scheduled_jobs`
  - `run_command`：沙箱内执行命令，可申请提权（严格、适中下要批准，宽松下直接运行）；不在工作区的会话在 `~/.ollupi/scratch` 里执行
  - 后台运行：工具可声明能在后台跑，`run_command` 和 `claude` 由模型每次调用时自己选；放到后台的调用立即返回"已开始"，这一轮接着做别的，结果作为报告写回这一轮；这一轮答完后等报告再接着回答；这一轮结束时没跑完的任务一起停下并报告，进程重启时被打断的任务报告为中断、不重跑，超过时限报告超时
  - `read_file`、`glob`、`grep`：读文件（带行号，按行分段）、按路径模式找文件（新的在前）、按正则搜内容（可带上下文）
    - 跳过 `.git`、`.gitignore` 忽略的文件和非文本文件，结果过长时截断
    - `glob` 只进入模式能匹配到的文件夹；遍历到上限时返回已找到的并标为截断，不再报错
    - 只读，不需要审批；沙箱禁读的路径（凭据、agent 数据、`config.yaml`）在任何沙箱模式下都不读，遍历时跳过并计数，指向它们的链接也不跟
    - 权限规则按路径匹配，如 `read_file(src/*)`
  - `edit_file`、`write_file`：只写沙箱允许的目录；审批的是冻结的 diff，执行前确认文件未被改过；规则可按路径匹配
    - `edit_file` 找不到 `old_text` 时，说明是哪一行、第一个不同的字符（全角空格、弯引号、空格代替制表符等），找到多处时列出行号；一批修改失败时说明一处都没改；成功时返回 diff
  - `web_fetch`：读取公网页面，HTML 转成 Markdown；只连公网地址，同域跳转跟随、跨域只返回新地址；按域名审批
    - 经用户的沙箱（Box）发出，和 MCP 服务器一样；本机走 macOS 网络设置里的系统代理（含 PAC，随开随关），没有时用 `HTTP(S)_PROXY`；由引擎提供，〔桌面〕不再自己加
  - 工具太多放不下时延迟加载，`load_tools` 按需载入
- MCP〔引擎〕
  - stdio 和 Streamable HTTP 两种传输，工具名 `<服务器>__<工具>`
  - 告诉 MCP 服务器是哪个会话在调用
  - 服务器是每个用户自己的，存在引擎里，随时增删改，改完关掉旧的、下次用到时启动；环境变量和 Headers 按写的原样保存和发送
  - 每个用户的服务器在自己的沙箱里运行，第一次用到时启动，掉线后下次用到时重启
  - 〔桌面〕后端启动时先连一次；服务器不进工作区沙箱，继承登录 shell 的环境变量（不含应用自己的 `OLLUPI_*`），在 `~/.ollupi` 下运行
- 浏览器工具〔桌面 sidecar〕：`navigate`、`snapshot`、`click`、`type`、`press_key`、`scroll`、`back`，操作的是会话在内置浏览器里当前显示的标签页
  - 由 Playwright 读页面和操作：页面读成无障碍快照，能操作的元素带 ref；iframe（包括别的网站的）和 Shadow DOM 里的元素也读得到、点得到；点击前等元素可见、可用、没被挡住
  - 长页面分页读：快照超过约 1 万 token 时分页，结尾写明共几页，`snapshot` 带 `page` 读其余页，同一份快照各页的 ref 都有效
  - 滚动作用于页面中间的那块区域，页面里自己滚动的列表也能滚
  - 会话不在屏幕上时也能操作它的标签页，按浏览器面板的大小排版
  - 不开调试端口：Playwright 经应用内的 CDP 代理连接，只连 agent 操作过的标签页，连不到应用自己的界面
- 能力页〔桌面〕：左侧列表切换技能、MCP、内置工具（窗口窄时变成上方一排），每页开头用一句人话说明
  - 技能：技能属于某一个 agent，按 agent 分区列出（主 agent、Super Agent、通用子 agent、浏览器子 agent、委派），每区一句说明它是谁，技能排成卡片宫格（窗口宽时多列），各自新建、导入文件夹；编辑 SKILL.md、删除（移到废纸篓）、复制给另一个 agent 都只动这个 agent 的那一份；保存时按后端的规则校验，不重启后端，agent 下一步就用上
    - "使用技能"开关、选择或更换技能文件夹（在可展开的"存放的位置"里）
    - 主 agent 的技能同时放进大、小两种模型各自的目录，换模型不丢
    - 首次启动默认开启，在 `~/.ollupi/skills` 里给主 agent 放入自带技能（`zhou-shenghua-woodcut-style`）；之后归用户管理，升级不覆盖
    - 后端启动时，把直接放在技能文件夹里的技能挪进主 agent 的两个目录；主 agent 已有同名技能的留在原处，由后端报错说明
  - MCP：添加 / 编辑 / 删除服务器，命令 + 参数 + 环境变量或 URL + Headers，保存即生效、不重启后端，显示连接状态（还没用到的写"用到时启动"）和工具数
  - 内置工具：按用途分组（文件和命令、网页、浏览器、计划、问你、帮手、记忆、技能、定时任务、长输出、找工具），每组一句说明，展开看工具名、说明和"只看不改 / 会改动东西 / 会接触外部"标记；MCP 工具列在各自服务器下

## 11. 定时任务

- 〔引擎〕5 字段 cron，按本地时区；到点向所属会话发一条消息，照常排队；暂停 / 恢复 / 删除；变更通知
  - 次数：发送（或发送失败）满 N 次后任务删除，排队中跳过的不算；不填则一直重复
  - 只执行一次：写明日期的 cron 加次数 1；cron 没有年份，最后一次运行在近一年后（日期已过）时拒绝创建或恢复
- 〔桌面〕
  - 按工作区筛选任务列表，显示下次运行、上次发送、已发送次数、暂停 / 工作区或会话已归档等状态
  - 新建任务：选工作区和会话、名称、时间（仅一次选日期 / 每小时 / 每天 / 工作日 / 每周 / 每月）、重复任务的次数、消息
  - 暂停、恢复、删除

## 12. 记忆

- 〔引擎〕
  - 记忆按用户开关：关着时会话不载入、不搜索记忆，也不从中提炼
  - 后台从已结束的 turn 提炼记忆，与已有记忆合并（新建 / 更新 / 废弃）；部署配了提炼用的模型才提炼
  - 学习也按用户开关：关着时照样载入和搜索已有记忆，只是不提炼；关着期间结束的 turn 直接跳过，打开后不补
  - 类型：偏好、决定、流程、事实
  - 范围：全局、无工作区（general）、各工作区
  - 会话开始时载入快照，压缩后再刷新；其余由 `memory_search` 搜索
  - 用户编辑或遗忘过的条目不被自动覆盖
  - 失败重试、跳过记录与状态查询
- 〔桌面〕
  - 按范围浏览、搜索记忆，编辑、遗忘、移到全局 / 移回；空的范围不列出；长条目先显示 3 行，可展开
  - 状态：记忆条数；记忆和学习都开着、且选了学习用的模型时显示待学习轮数、失败原因与重试时间（提醒色）、跳过记录，否则不显示
  - 设置（只在"全局"里）：记忆开关、从会话中学习开关（都是拨动即生效）；学习开着时选学习用的模型（会消耗模型 token，更换会重启后端）

## 13. 模型〔桌面 + 引擎〕

- 三种 API：OpenAI 兼容、Anthropic、Gemini；模型以 `提供方/名称` 选择
  - Anthropic / Gemini 用原生接口：思考内容和签名原样回放，Anthropic 自动缓存断点、Gemini 隐式缓存
- 〔引擎〕请求被拒（408、429、5xx）或中途断开时重试 8 次，等待从 0.5 秒翻倍到 8 秒，等待时占着调用名额；提供方 3 分钟没有任何返回就放弃这次尝试
- 添加 / 编辑 / 删除提供方：API 类型、名称、Base URL、API 密钥
  - 添加时先选服务：DeepSeek、通义千问、Kimi、智谱 GLM、OpenAI、Anthropic、Gemini 预设好接口和地址，只需粘贴密钥，名称、接口、地址收在"高级"里；"其他…"手动填写全部字段
  - 模型行用人话写能力：能看图、先想再答、最多读 / 写多少 token、同时几个请求
- 显示提供方账户余额〔桌面〕：DeepSeek、Moonshot、SiliconFlow、OpenRouter（需管理密钥）按 Base URL 识别，用已填的密钥查询；打开设置时查询、5 分钟内不重复，可手动刷新；其他提供方或查询失败时不显示
- 按 API 类型自动拉取模型列表，筛选、批量勾选
  - 上下文、最大输入、输出上限能拿到的都自动填入，留空时上下文取 128000、输出取 8192 和上下文四分之一里较小的，最大输入按窗口算：OpenAI 兼容接口读模型上或 `model_info` 里的字段（DeepSeek 给上下文和输出）；百炼的兼容地址改问它自己的列表接口，只列输出文本的模型，问不到时退回兼容列表
  - 手动添加或编辑模型时，名称对上列表里的模型也自动填入
- 每个模型：上下文 / 输出上限、可选的最大输入、并发调用数、思考开关、是否支持图片
- 设默认模型、标出记忆所用模型
- 提供方的模型列表可折叠，超过 5 个模型时默认收起
- 保存时由后端校验，再重启后端

## 14. 设置与外观〔桌面〕

- 设置页和记忆、能力一样保留主侧边栏；所有设置在一页，左侧列出通用、脱敏、通知、外观、语言、权限、模型、飞书机器人（权限、模型和飞书机器人要等后端返回才显示内容，放在最后，免得加载后把上面的内容往下推），点击跳到对应位置，滚动时高亮当前所在的分类
- 通用：每行一项和对它的操作——版本号与检查更新、应用日志、数据文件夹（`~/.ollupi`）、`config.yaml` 的路径与打开、浏览器历史与清除、后端状态与重启后端
- 权限：所有会话的默认审批策略和规则（用户这层），不设时用默认的适中；保存即生效，不重启后端
- 通知：需要审批、需要回答、一轮完成、一轮失败分别开关；只在应用不在前台时显示，点击打开对应会话；Dock 角标显示等你处理的会话数
- 关闭窗口只是隐藏：应用和后端留在后台，照常通知；点 Dock 图标回来，⌘Q 才退出
- 界面无响应时弹窗提示，可重新加载界面；重新加载后回到原来的会话，agent、会话和浏览器标签页继续运行
- 语言：跟随系统 / English / 简体中文
- 外观：主题和明暗，字体 Manrope + 苹方
  - 主题：石与苔（默认：石色和纸色的大圆角工作面，苔绿做动作色，赭色只表示"需要你"，六种低饱和区域色区分工作区）/ 暮色（底色上渗进黄昏的光和看得见的颗粒，光滑的纸面浮在上面，暮靛做动作色，粉彩区域色，侧栏顶部的蜻蜓、新会话页的草原地平线、空状态小狼脚边的草和萤火）；设置 → 外观里用两张小预览卡选，方向键可切换
  - 明暗：跟随系统 / 浅色 / 深色，每套主题都有浅色和深色
  - 细节：流式输出末尾的块状光标、加载时依次变深的三个圆点（附动词）、运行中呼吸的圆点；App 图标是燕麦底上坐在月亮前的小狼，暮色主题下 Dock 图标换成黄昏里的小狼；侧栏顶部显示 ollupi 字标
  - 小狼：空状态里换成不同姿势的小狼（会话没有消息、记忆为空、搜索没结果、没有定时任务、技能为空或关着），第一次打开时新会话页有圆形标识，设置 → 通用顶部有"关于 Ollupi"
- 检测 `config.yaml` 与后端实际使用的配置不一致

## 15. 飞书机器人〔桌面〕

- 在手机上通过飞书（或 Lark）机器人操作会话，sidecar 用长连接接收消息和卡片回调，Mac 不需要公网地址；设置步骤见[飞书机器人](/zh/app/feishu)
- 只为名单里的 open_id 操作；其他人发来消息只回复对方的 open_id；只处理单聊
- 会话与话题
  - 给机器人发一条消息：在设置的工作区（或不属于任何工作区）开始会话，标题取消息开头，机器人在这条消息下开话题
  - 在桌面端或由定时任务开始的会话，有内容要显示时（开始一轮、审批、提问），机器人给名单里第一个人发一条写着"工作区 · 标题"的消息，在它下面开话题，之后和飞书开始的会话一样
  - 在话题里发消息：作为会话的下一轮，有一轮在跑时排队并回复"已排队，前面的消息处理完后回复"；桌面端或定时任务发来的一轮在卡片上写出它收到的消息；发 `/stop` 停止当前轮
  - 话题和会话的对应关系存在数据目录里，重启后保留；删除会话时一起删掉
  - 支持文字和富文本消息
- 每一轮一张卡片：agent 的消息和工具调用按顺序追加，约每秒更新一次；运行中有"停止"按钮，结束后标出完成 / 已停止 / 失败；桌面端或定时任务发起的轮次注明来源；过长时只保留后面的内容
- 审批卡片：工具、命令或文件改动、需要完全访问时的说明；允许一次 / 在此会话中允许 / 拒绝（"总是允许"留在桌面端）；子 agent 的审批也发到父会话的话题
- 提问卡片：每个问题可选选项或自己写，一次提交
- 审批和提问在飞书或桌面任一端处理后，卡片改成处理结果和处理的地方
- 设置 → 飞书机器人：App ID、App Secret、平台（飞书 / Lark）、为谁操作、新会话所在的工作区；保存时由后端校验并重启，可停用

## 16. 后端托管〔桌面〕

- 启动、监督、重启 sidecar 后端（`ollupid`），握手后连接
- 启动失败时显示原因（超时、无法启动、意外退出）和后端日志
- 后端日志写到 `~/Library/Logs/Ollupi/backend.log`，超过 10MB 时换新文件；设置 → 通用 → 应用日志里可以打开
- 连接状态：已连接 / 启动中 / 已停止 / 重新连接
- 协议版本不一致时提示

## 17. 协议〔引擎〕

- WebSocket 上的 JSON-RPC 2.0，方法名对齐 Codex app-server
- 一张表同时分发请求并生成 `protocol.schema.json`，界面类型由它生成；测试检查 schema 和表一致、枚举值和代码里的常量一致
- 每种关闭码和握手拒绝之后客户端该怎么做（随机等最多 10 秒后重连、退避重连、按 `Retry-After` 重连、不自动重连）也写在契约里
- 每个客户端每秒最多 50 条消息，可突发 200 条；单条消息最大 4 MB

## 18. 安装与更新〔桌面〕

- macOS 12+，Apple 芯片（arm64）DMG
- 从 GitHub Releases 自动检查更新，下载并安装，立即重启或退出时安装；设置 → 通用的版本一行里手动检查
- 已是最新时显示当前版本号；显示更新内容，失败可重试；应用不在可替换位置时提示移到"应用程序"
